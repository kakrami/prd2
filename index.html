How Assessment status works
Assessment includes only plan records where Method of Delivery is Assessment. A matching Delivered assessment/service-family entry on or before the plan End Date marks it Completed. Incomplete assessments are yellow within 30 calendar days of End Date and red after End Date. Provider changes are accepted when the child and service family match.
Service Frequencies
Cross-references service-plan frequency requirements with the unified visit dataset
No service-plan frequency data
Import a service-plan workbook to evaluate first ongoing visits and recurring frequency.
How Frequency status works
Frequencies contains ongoing-service requirements only. A Delivered assessment starts the First Ongoing Visit clock; Assessment deadlines are tracked separately. The first ongoing visit is due within 30 days and any qualifying submitted entry, including a cancellation, satisfies it. Recurring frequency begins the month after the ongoing Start Date. Any provider may fulfill the same child + service-family requirement. Data Coverage is audit context only and never overrides Met, In Progress, Due Soon, or Behind.

Delivered status values
These values identify completed visits. Negative outcomes such as “Not Delivered” are never counted as Delivered.
One value per line or comma-separated. Defaults: Delivered, Delivery, Completed, Complete.

Frequency rules
Frequency tracking covers the ongoing-service lifecycle by child and service/discipline family. A Delivered assessment establishes the completion date used to start the First Ongoing Visit clock; assessment deadline status is tracked separately in the Assessment tab. First Ongoing Visit and recurring Frequency both count qualifying submitted service entries, including cancellations. Recurring frequency then uses plan-anchored whole-month windows starting with the month after the ongoing plan Start Date: Month = 1 month, Quarter = 3 months, Biannual = 6 months, Annual = 12 months.
Count completed assessment toward recurring frequency
Enabled by default. When the completed assessment falls inside an active ongoing frequency window for the same child and service family, it can satisfy one required entry in that window. Recurring frequency does not begin until the month after the ongoing Start Date. The separate first ongoing visit within 30 days is still required.
Due-soon warning
Calendar days before the requirement due date. Default: 5 days. Before this window, an unmet requirement remains In Progress and does not affect provider attention status.
Ignore services for ongoing frequency
Planned services matching this list are excluded from ongoing-frequency tracking, including the First Ongoing Visit and recurring frequency windows. The Assessment tab is unaffected by this ignore list.
One service name or keyword per line or comma-separated. Matching uses whole words/phrases. Defaults: Service Coordination and SC. Leave empty to assess ongoing frequency for every service.
Supported Frequency & Intensity patterns
2*.75hr /Quarter, 1*.75hr /Month, 2*1hr /Month, and 1*1hr /Biannual. Frequency tracking uses the number before *; intensity is retained for reference. Recurring windows are anchored to the month after the Start Date, not standard calendar quarters. Month = 1 month, Quarter = 3 months, Biannual = 6 months, Annual = 12 months. Example: Start Date Feb 12 + Quarterly = Mar 1–May 31; the next window is Jun 1–Aug 31. The End Date month caps the final window. Any qualifying entry anywhere inside a recurring window counts. Recurring frequency is satisfied by Child ID + Planned Service regardless of which provider submitted the matching visit; the planned provider remains visible for reference and the actual fulfilling provider is shown separately. Assessment and First Ongoing Visit rules use exact dates.
Column matching
Visit logs and service-plan/frequency workbooks use separate schemas. The app detects the sheet type from its headers, then applies the matching aliases below.
How matching works: it is case-insensitive, and spaces, underscores, and hyphens are treated as equivalent. For example, SERVICE_DATE, Service Date, and service-date all match the same way. Aliases below are shown exactly as entered so the supported source names are easy to see.
