The importer recognizes common header variations automatically (for example SP_NAME, SERVICE_TYPE_NAME, SERVICE_DATE, and SERVICE_LOG_ENTER_DATE). If a required field cannot be identified confidently, you will be asked to map it. Tab-separated Excel paste and CSV are supported. Settings
Manage import rules, frequency rules, saved column mappings, and imported data sources.
Visit status definitions
Define how values from REASON_NAME / Status are interpreted. Source aliases are checked in the order shown under Column Matching, so REASON_NAME is preferred when both columns exist. Matching is case-insensitive and recognizes each value as a whole word or phrase inside a longer status.
Delivered status values
These values identify completed visits. Negative outcomes such as “Not Delivered” are never counted as Delivered.
One value per line or comma-separated. Defaults: Delivered, Delivery, Completed, Complete.
Cancellation status values
These values identify intentional cancellation outcomes for time accounting. A matching REASON_NAME / Status value is automatically assigned 15 minutes and is not flagged as a missing/invalid time entry. This does not change the overall cancellation-rate rule: every non-Delivered visit still counts as non-Delivered.
One value per line or comma-separated. Defaults: Cancelled, Canceled, Cancellation, CX. Example: “CX - Family unavailable” matches CX.

Frequency compliance
Control how planned service frequencies are compared with uploaded visit logs. The app uses calendar months, quarters, half-years, and years and avoids marking incomplete coverage as noncompliant.
Count toward planned frequency
All submitted visit entries is the default because frequency is being measured by entries submitted. Choose Delivered visits only if your program requires completed visits for frequency compliance.
Require complete uploaded data coverage before marking Behind
Recommended. If a month, quarter, or half-year is cut off by the available visit exports, the period is labeled Incomplete Data instead of Behind.
Supported Frequency & Intensity patterns
2*.75hr /Quarter, 1*.75hr /Month, 2*1hr /Month, and 1*1hr /Biannual. Compliance uses the number before *; intensity is retained for reference but does not change the required visit count.
Column matching
Visit logs and service-plan/frequency workbooks use separate schemas. The app detects the sheet type from its headers, then applies the matching aliases below.
How matching works: it is case-insensitive, and spaces, underscores, and hyphens are treated as equivalent. For example, SERVICE_DATE, Service Date, and service-date all match the same way. Aliases below are shown exactly as entered so the supported source names are easy to see.
